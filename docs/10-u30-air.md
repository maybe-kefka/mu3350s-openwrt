# 10 U30 Air（U30AirV1.0.0B33，32 GB 版）—— BROM 刷 root + 内置存储安装 OpenWrt

> 本页是 **U30 Air** 的完整流程。F50/MU3350S 走 TF 卡安装，见 [05 OpenWrt 安装](05-openwrt-install.md)。
> 2026-11-03 在一台 `U30AirHW1.0` / `U30AirV1.0.0B33`（31.27 GB eMMC，无卡槽）上完整跑通。

## 1. 与 F50 的差别（为什么需要单独一套流程）

| 项目 | F50 / MU3350S | U30 Air（B33） |
|---|---|---|
| 固件 | F50_ST_ESIMV1.0.0B04 | **U30AirV1.0.0B33** |
| 存储 | 64 GB + TF 卡槽 | 32 GB 版（29.1 GiB），**无卡槽**，userdata 填满磁盘 |
| 原厂 USB 调试开关 | `USB_PORT_SETTING` 可用（开机会有 10 秒 ADB 窗口） | **不可用**，`usb_port_switch` 恒为 0，无公开 ADB 方案（UFI-TOOLS issue #146） |
| 取 root 的路径 | 开机 ADB 窗口 → Samba `root preexec` | **BROM 刷第三方 one-key-root 包**（patched trustos + Magisk boot，自带无线 ADB）→ 再用 Samba 通道拿持久 root |
| 安装位置 | TF 卡 ext4（不动 Android 数据） | 内置 eMMC：收缩 userdata 划出 8 GiB（**会清 Android 数据**，实验性） |
| 5G | eSIM 保留 | 物理/eSIM 由原厂 Android 保留；Linux 通过 sipa_eth0 共用 |

> 锁 BL 的 B33 没有“软”路径：`USB_PORT_SETTING` 失败、无 telnet、无 recovery 分区语义，
> 社区唯一的公开方法是按住电源键进 **BROM** 后再写 boot/trustos。

## 2. 设备事实（实测）

- SoC：Unisoc UMS9620 / T760；eMMC 61,079,552 扇区（29.1 GiB；#386 的作者记 31.27 GB）
- A/B 槽：Android 在 **a** 槽；`trustos_a != trustos_b`、`uboot_a != uboot_b`、`sml_a != sml_b`（出厂后刷过 OTA）
- 分区：75 个；`splloader` 单份 256 KiB；`uboot_a/b` 各 5 MiB；`boot_a/b` 各 **64 MiB**；`trustos_a/b` 各 **6 MiB**
- `userdata` 23,828 MiB，结束于磁盘末尾 → **没有任何空闲空间**（32 GB 版）
- USB：正常开机 `19D2:0246`（RNDIS+WPD，192.168.0.1）；下载模式 `1782:4D00`（"SPRD U2S Diag"）

## 3. 进入 BROM / 下载模式

两种方式（任选）：

1. **spd_dump 直连（实测可用）**：设备关机，运行 `spd_dump --wait 60 --kickto 2 …`，然后插线。
   本机看到 `Successfully connected to port: N` 后很可能 `kick reboot timeout` —— **这时设备已停在 BROM**，
   保留现场，改用 BROM 直连命令接管（见下）。这正是 `scripts/u30-flash-root.mjs` 的前置状态。
2. **按键方式（#386 作者用法）**：完全关机，按住电源键约 5~8 秒的同时插入 USB-C（直插、不经 hub）。
   设备枚举为 `1782:4D00`。

BROM 直连命令（CVE-2022-38694，绕过 brom 对 fdl1 的签名校验）：

```
spd_dump.exe --wait 30 --verbose 1 exec_addr 0x65012f48 \
  fdl bin\fdl1-dl.bin 0x65000800 fdl bin\fdl2-dl.bin 0xb4fffe00 exec
```

⚠️ 热重启进不了 boot_diag（实测 `--kickto 2` 在 warm reboot 后必然 `find port failed`），必须冷启动。

## 4. 第一步：完整备份（只读）

```powershell
# scripts/U30-备份.cmd（等价于 u30-backup.ps1）
# 按提示：拔线 → 长按电源键 10 秒关机 → 回车监听 → 插线
```

- 读取 **73 个分区**（`r all`，跳过 userdata/cache/blackbox），约 5.3 GB（含 `super` 2 GB、`fulldumpdb` 2 GB）
- 备份 SHA-256 清单见 [`artifacts/u30air-backup-manifest.sha256`](../artifacts/u30air-backup-manifest.sha256)
- 关键值：`boot_a` 64 MiB、`trustos_a` 的 DHTB 镜像 5,035,672 B、`splloader` 65,240 B
- 备份目录建议放仓库之外（如 `C:\f50-work\u30-backup`）

## 5. 第二步：刷第三方 one-key-root 包（patched trustos + Magisk boot）

包结构（社区 `U30AirV1.0.0B33.tar.gz`，本仓库不分发二进制）：

| 文件 | 大小 | SHA-256（本机核对） | 写入分区 |
|---|---|---|---|
| `boot.bin` | 67,108,864 | `62a35968c3d1deb92a1d1d473af3eb311aec7c7c19d90920d79701d9e841da63` | `boot_a` |
| `trustos.bin` | 5,178,856 | `55cad8db09639b1dbd718ae62b481b87f19509be4e3738dd35dfa5852a405dd9` | `trustos_a` |

**为什么先验证再刷**：解包 `boot.bin` 的 ramdisk（LZ4 legacy，偏移 38,367,232，1,274,910 B）可以看到：

- `overlay.d/adbip.rc` + `overlay.d/sbin/start_adbip.sh`：开机 late-start 以 root 运行，设置
  `persist.service.adb.tcp.port=5555`、启动 adbd（刷完后**自动开无线 ADB**）
- `system/etc/ramdisk/build.prop`：`ro.product.bootimage.device=U30Air`（确认是 B33 专用 boot）
- `.backup/.magisk`：`KEEPVERITY=true KEEPFORCEENCRYPT=true`

**写入顺序（重要）**：`trustos_a` 先、`boot_a` 后；每次写完立即回读校验。
`trustos.bin`（5,178,856 B）比 6 MiB 分区小，因此用 **`wof trustos_a 0 <file>`**（偏移写，绕过大小检查），
`boot.bin` 与分区等大，用 `w boot_a`。

```powershell
# 设备已在 BROM/下载模式后：
node scripts/u30-flash-root.mjs --spd C:\f50-work\part-tool\bin\spd_dump.exe `
     --fdl1 C:\f50-work\part-tool\bin\fdl1-dl.bin --fdl2 C:\f50-work\part-tool\bin\fdl2-dl.bin `
     --pkg C:\f50-work\part-tool\data --work C:\f50-work\u30-flash-tmp

# 回滚（用备份写回）：
node scripts/u30-flash-root.mjs ... --rollback --backup C:\f50-work\u30-backup
```

实测输出：`Write Part Done: trustos_a, target: 0x4f05e8`、`Write Part Done: boot_a, target: 0x4000000`，
回读 SHA-256 与包一致 ✅（B33 只在改 **uboot** 时被拒，boot/trustos 可写——issue #386 的结论）。

重启后：正常 Android 启动（`19D2:0246`），**无线 ADB 在 5555 端口自动监听**（`ro.adb.secure` 仍为 1，
但 overlay 的 `persist.adb.secure=0` 生效，无需在设备上点授权）。

## 6. 第三步：持久 root 通道（Samba `root preexec`）

与 F50 相同原理，**但共享名是 `U30 Air`**：

```
/data/samba/etc/smb.conf   (rwxrwxrwx)
  [U30 Air]
      root preexec = /system/bin/sh /data/local/tmp/root.sh
      ↑ smbd 以 root 运行，任意 SMB 连接触发 → socat TCP:4444 EXEC:/system/bin/sh
```

```powershell
adb connect 192.168.0.1:5555
adb push socat /data/local/tmp/socat          # UFI-TOOLS APK 内 assets/shell/socat
node scripts/f50-root-shell.mjs trigger       # 自动尝试 F50 / U30 Air 共享名
node scripts/setup-device-root.mjs            # 部署 /odm/bin/su 兼容层 + adbd TCP 持久化
adb shell su -c "id"                          # -> uid=0(root) context=u:r:su:s0
```

Windows 若报 `1272`（禁止来宾 SMB），管理员执行一次：

```bat
reg add HKLM\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters /v AllowInsecureGuestAuth /t REG_DWORD /d 1 /f
```

## 7. 第四步：安装 OpenWrt（32 GB 版：收缩 userdata）

安装器检查结果（`-Check`）：

```
eMMC: 29.1 GiB, partitions end at 21.1 GiB, free after them 0.0 GiB
userdata 23.3 GiB, encrypted/file; keep 不可行（f2fs helper errno=22）
Linux 至少 0.8 GiB（OpenWrt），Android 至少保留 4.0 GiB
→ 走 reset：改写 GPT（userdata 23.27→15.27 GiB，划出 8 GiB 的 mu300root 区域）
```

答案文件：[`answers/u30air-internal-answers.example.txt`](../answers/u30air-internal-answers.example.txt)
（复制为 `answers/u30air-internal-answers.txt` 并改密码；该文件已被 git 忽略）。

```powershell
node scripts/patch-mu300-installer.mjs --installer C:\f50-work\mu300-src\install.ps1
powershell -ExecutionPolicy Bypass -File scripts\installer\install-openwrt.ps1 `
  -SrcDir C:\f50-work\mu300-src -AnswersFile answers\u30air-internal-answers.txt
```

### 实测中的一个重要偏差（务必了解）

安装器准备的是「reset」路径：写新 GPT → 在区域首部写 token → 往 `misc` 写 recovery 的 `--wipe_data` 命令 → 重启，
期望 Android recovery 恢复出厂。**但这台 U30 Air 的启动器没有执行该 BCB**（该机身没有独立 recovery 分区语义）：

- 设备重启后 Android 正常启动，`/data` 数据仍在；
- userdata 分区确实缩小到 15.27 GiB，但 f2fs 回滚到了更早的检查点（`/data/local/tmp` 里文件 mtime/内容退回旧版本，
  ctime 为重启时刻）——**Android 数据处于不一致状态**；
- `misc` 首 2 KiB 已被清空（无挂起 wipe），之后没有再触发恢复出厂。

对「装 Linux」没有影响：事务恢复校验只比对设备/槽位/GPT/区域/token/安装器身份，通过后继续安装；
因此**第二次运行安装器即完成 Linux 安装**。但如果你还要用 Android，请在 Android 里手动恢复出厂一次。

然后安装器会：

- 创建 ext4 `mu300root`（8 GiB，loop 挂载）并解压 OpenWrt LuCI（内核 7.3.1）
- **同步 b 槽启动链**：`uboot_b ← uboot_a`、`sml_b ← sml_a`、`teecfg_b ← teecfg_a`（先备份原镜像，逐个回读校验）
- 写 `boot_b`（Linux boot 镜像）、`misc` 的 32 字节 `bootloader_control`，把 active slot 设为 **b**
- 装 Magisk 模块，之后在 Android 上 `su -c mu300-linux` 可切回 Linux

## 8. 第五步：内置 mihomo 透明代理（已验证）

```powershell
node scripts/install-mihomo.mjs --sub "https://…/link/…?clashmeta=1" --secret "change-me"
```

脚本会下载 mihomo（arm64，GitHub release，可走 `--mirror https://gh-proxy.com`）、metacubexd，

## 10. 回滚 / 救砖

- **分区级恢复**：BROM + `spd_dump` 用 `artifacts/u30air-backup-manifest.sha256` 对应的备份文件逐个 `w` 写回
  （`boot_a`/`boot_b`/`trustos_a`/`trustos_b`/`uboot_a`/`sml_a`/`teecfg_a`/`vbmeta_a` 等）；
  `trustos` 这类小于分区的镜像用 `wof part 0 file`。
- **切回 Android**：Linux 里 `mu300-next-boot android && reboot`；GPT/userdata 不再改动。
- **重刷原厂**：官方完整固件可由 FDL 的 `write_parts`/PAC 流程处理（本仓库不分发固件）。
